# 0002 — M1 end-to-end integration contract

**Recorded:** 17 September 2026 · **Base:** `codex/21-verify-accept` at `44afe42` (two commits past the `2142672` cited in the orchestrator brief; both verified) · **Status:** provisional, operator-authorized development path

## 1. Purpose and status

This record is the brief for the parallel agents that turn the provisional Go core into a system a user drives on this Mac with `gafferd`, `gaffer-runner` and `gaffer`, proven with real binaries. It adds the missing edges: execution channel, owner API and CLI, supervisor with launcher, isolation profile, inference boundary and guardian, evidence-gated finalization, reconcile-before-retry and paused restore.

Status claims are narrow:

- The only profile that runs code is `macos-sandbox-exec-dev`, recorded as `qualification: development`, `supported: false` in every eligibility record, journal, dispatch input and verification report, and refused unless `gafferd --allow-development-profile=macos-sandbox-exec-dev`, `gaffer-runner --isolation-profile=macos-sandbox-exec-dev` and the approving owner's `--allow-development-isolation` agree. No supported unattended runtime, #89 proof or #9/#10 acceptance follows.
- `gaffer-runner` (supervisor and guardian) is inside the trust boundary: it holds the gateway credential and issues supervisor evidence; the sandboxed job is not. Runner-authenticated writes still require machine-verifiable completeness, never a bare success flag.
- Model access is a configured **model gateway endpoint** plus **credential reference** (CLIProxyAPI today; 9Router remains one implementation), using PR #113's vocabulary (`docs/contracts/model-gateway.md`); Gaffer never becomes an account router or quota ledger.
- Execution, local acceptance, publication and merge stay distinct; no publication or merge route exists.

## 2. Vocabulary

- **model gateway endpoint** — Operator config `gateway-config-v1`: `gateway_id`, `base_url` (HTTPS), `credential_ref`, `protocols[]`, `models[]`. Owns provider credentials, accounts, rotation, fallback.
- **credential reference** — `{kind:"file", path}`; mode 0600, read once by the supervisor, held in memory, never written.
- **inference boundary** — Per-attempt loopback proxy inside `gaffer-runner` that injects the gateway credential, pins protocol/model allowlists and journals reservations and receipts. The worker sees only a scoped token.
- **execution profile** — (harness, protocol, isolation profile ID, limits profile) carried in `authority.Route`.
- **isolation qualification** — `unqualified` (default, refuses launch), `development` (`macos-sandbox-exec-dev`, explicit), `test-only` (`test-only-unconfined`, Go tests).
- **execution channel / owner listener** — Second TLS listener with ALPN exactly `execution-provisional-v2`, HTTP/1.1 under `/x/v1`, runner mTLS only; versus the existing HTTPS listener serving the identity API and `/api/v1` workflow routes under owner mTLS.
- **generation / daemon_boot / runner_boot** — Store lifetime UUID; daemon incarnation; supervisor process incarnation (one per `gaffer-runner` process, shared by its journals).
- **lease** — Daemon-issued `lease_reply` committed before send; runner cutoff `stop_by = S + V - D - T`.
- **custody / receipt / result head** — `CustodyResult` durable promotion; its `receipt_id`; the `artifact_result_heads` row naming the task's current finalized result.
- **finalize** — Evidence-checked CAS `result_pending -> succeeded|failed` plus `dispatch_releases` in one transaction.
- **guardian** — helper process outside the job's process group that launches, deadlines and kills the job even if the supervisor dies.

## 4. Execution channel wire contract

**Listener.** `identity.ExecutionTLS(certFile, keyFile)` equals `ServerTLS` except `NextProtos = []string{p.FencedVersion}`. Go's `net/http` closes any TLS connection whose negotiated ALPN is neither `http/1.x` nor registered in `TLSNextProto`, so `httpapi.ExecutionListener(inner net.Listener, cfg *tls.Config, handshake time.Duration) net.Listener` wraps `Accept`: it runs `tls.Server(raw, cfg).HandshakeContext` under the timeout, closes the connection unless `NegotiatedProtocol == p.FencedVersion` and `identity.Fingerprint` succeeds, and returns an opaque `*execConn` (not a `*tls.Conn`), so `http.Server` serves HTTP/1.1. `Server.ConnContext` stores the `tls.ConnectionState`; handlers read it with `httpapi.ExecutionState(ctx) (tls.ConnectionState, bool)`. `cmd/gafferd` runs a **separate** `http.Server{ReadHeaderTimeout: 5s, ReadTimeout: 150s, WriteTimeout: 150s, IdleTimeout: 60s, MaxHeaderBytes: 8192}` on `--execution-listen IP:port` (required with `--tls-cert`); the owner server keeps its 3 s timeouts. Client `internal/execclient`: HTTP/1.1 only (`ForceAttemptHTTP2=false`, `Proxy=nil`, no redirects), `TLSClientConfig{NextProtos: [p.FencedVersion], MinVersion: TLS1.3, client cert}`, `DialTLSContext` verifying the negotiated protocol and `--daemon-fingerprint`. `selected` passed to store methods is the ALPN read from the connection, never a body field.

**Conventions.** Package `internal/execwire`, `Version = "execution-channel-provisional-v1"`; closed JSON bodies (`DisallowUnknownFields`, no nulls, ≤ 64 KiB except blobs). Every request re-authenticates the peer (`store.Authenticate`: role runner, enabled, not revoked; else 403 `identity_denied`) and, except `POST /x/v1/session`, requires `X-Gaffer-Session: <session_id>` (else 409 `session_stale`). Error body `{version, error, detail}`; codes are `authority` Deny codes and `protocol` refusals verbatim plus `alpn_refused`, `session_stale`, `busy`, `store_unavailable`, `stream_sequence_gap`, `stream_record_conflict`, `upload_incomplete`, `digest_mismatch`. Pools: `control` 16/2 s, `long` 8/30 s, `bulk` 2/120 s.

Routes under `/x/v1` (pool; body → reply; store method; durable point; status/replay):

- `POST /session` (control): `Hello{version,message_id,runner_boot,eligibility_id,eligibility_revision,policy_digest,journals[]}` → `Session{session_id,generation,daemon_boot,daemon_fingerprint,runner_id,mode,drift_ms:2000,termination_ms:5000,lease_validity_ms:20000,renew_every_ms:5000,paused}`; `RunnerSession`, then `reconcile.OnHello`; durable: `runner_sessions` row; 200; `mode:"recovery_only"` when the runner's latest eligibility does not carry `runner_boot` (evidence accepted, no launch); same `message_id` → same row
- `GET /state?dispatch_id=` (control): → `State{attempt_state,revision,acknowledged,released,last_lease,stream,receipt_id,head,stop_targets[],paused}`; `ExecutionState`; durable: read; 200/404
- `GET /input?dispatch_id=` (control): → `execwire.TaskInput{version,dispatch_id,task_id,repository,base_commit,brief_sha256,brief,criteria[{id,text}],paths[],operations[],harness,settings}` from retained `task_briefs`; `repository` is the repository ID, lists are arrays (never null), and `settings` is a harness-specific object. `CreateTask` normalizes and persists the brief; `store.BriefDigest` / `workflow.TaskDigests` compute SHA-256 over canonical JSON `{brief,criteria,paths,operations,harness,settings}` in that key order with sorted settings keys and no whitespace. The stored, grant-bound and runner-recomputed `brief_sha256` must be byte-identical before use; drift refuses `reconciliation_required`. Input is data, not execution authority.
- `GET /inbox?wait_ms≤25000` (long): → `Inbox{assignments[]store.Dispatch,cancels[]p.Message,paused,poll_after_ms}`; `PendingAssignments` + `Delivery` per id, `PendingCancels`; durable: `Delivery` commits `expireGrants`; 200; wakes on `notify.Hub`; refused deliveries are not sent
- `POST /messages` (control): `MessageEnvelope{version,message_id,dispatch_id,message,evidence?,boundary?,measurement?}` → `{outcome,message?}`; by kind (below); durable: tx commit; 200; equal replay → same outcome; changed → 409 `identity_conflict`
- `POST /lease` (control): `LeaseEnvelope{version,message_id,dispatch_id,request}` → `lease_reply` or `refuse`; `IssueLease`; durable: `control_leases` row; 200; 409 `refuse{reason}` after fence commit; same nonce → retained reply
- `POST /streams/{attempt_id}` (bulk): `StreamBatch{version,records[]runstream.Record}` ≤ 64 KiB, contiguous; `runstream.Sinks.Receive`; durable: sink fsync per record; 200 `StreamAck{through,expected,bytes}`; 409 `stream_sequence_gap` with `expected`; 409 `stream_record_conflict`; duplicates → retained ack
- `POST /attempts/{id}/uploads` (control): `UploadBegin{version,message_id,result,manifest_base64}` → `UploadSession{upload_id,missing[]{sha256,bytes},bytes_allowed}`; `BeginUpload`; durable: `upload_sessions`, `upload_blobs`; 201; replay by `message_id`; attempt must be `result_pending`
- `PUT /uploads/{upload_id}/blobs/{sha256}` (bulk): raw bytes, exact `Content-Length` 0..64 MiB; `RecordUploadedBlob`; durable: temp file hashed, fsync, rename, dir fsync; 201 new, 200 duplicate, 422 `digest_mismatch`, 413 over 256 MiB per attempt
- `POST /uploads/{upload_id}/commit` (bulk): `{version,message_id}` → `CommitReply{ack,receipt,quarantined}`; `CommitUpload` → `CustodyResult`; durable: custody + metadata commit; 200; 409 `upload_incomplete` listing missing digests; lost reply → byte-identical ack
- `POST /attempts/{id}/finalize` (control): `Completion{version,message_id,receipt_id,stream{through,digest},exit{code,pgid,observed_unix_ns},boundary}` → `{outcome,released:true}`; `FinalizeAttempt`; durable: CAS + event + release + head in one tx; 200; 409 `reconciliation_required` (incomplete evidence) or `stop_latched`
- `POST /usage` (control): `Usage{version,message_id,identity,receipts[]}`; `RecordUsage`; durable: `attempt_usage` upsert; 200; replayable

`POST /messages` kinds:

- `accept` → `AcknowledgeAssignment(fingerprint, dispatch_id, message)` → `{outcome:"acknowledged"}`.
- `refuse` → `runtime_observations(kind:"refused")` → `{outcome:"recorded"}`; reconcile classifies `refused_before_accept`.
- `transition` → `ProposeTransition`. Proposals and required `evidence.kind`: `assigned→starting` (`launch_intent`: workspace, `boundary_port`, nonce and `guardian_pid: 0` because the guardian is not yet spawned; nonzero guardian PID is malformed; a current lease is required). The port is exactly 0 for `fake`, otherwise 1..65535. `starting→running` requires `launched` with real, nonzero `guardian_pid`, `pid`, `pgid`, `start_unix_ns`; `running→result_pending` (`exit`: code, empty-pgid observation, `stream_through` equal to the sink watermark); `assigned|starting|running|result_pending→stopping` (a `control_targets` row exists or `stop_id == execwire.ExpiryStopID(last nonce)`). Daemon checks runner, boots, generation, `dispatchAllowed`, `CheckTransition`; stores evidence in `runtime_observations`; sets `tasks.state` (`result_pending→verifying`, `stopping→reconciling`); returns the recorded message. Proposals to terminal states or `unknown` are refused `invalid_transition`.
- `terminated` → `ReportTermination(fingerprint, selected, c.Evidence, boundary)`: validates as `ObserveTermination` does (target, boots, `validControlEvidence`) through the factored `observeTerminationTx`; for `stop_id == ExpiryStopID(nonce)` it first latches `c.Request{ID, Kind: CancelAttempt, Cause: "lease_expired"}` via `latchStop` (actor `"lease-clock"`); inserts `control_observations`; then, only if `boundary.quiescent` (reservations == terminal receipts, in-flight 0) **and** the attempt is `stopping|unknown`, calls `releaseDispatchTx` to `cancelled` or `expired` with `dispatch_releases.actor` = runner principal. Otherwise the attempt stays `stopping|unknown` with `remote_work:"unknown"` and the reply is `{outcome:"observed", released:false}`. Old-boot evidence is retained in `runtime_observations` (`{outcome:"retained"}`) for reconcile.

**Lease service.** `IssueLease` is `RecordControlLease` without `owner()`: S0 factors `issueLeaseTx(ctx, tx, provenance, dispatchKey, selected, request, reply, margin)` out of `control.go`; `RecordControlLease` keeps its owner-only signature and delegates. The daemon builds `lease_reply{nonce, boots, validity_ms: 20000}` (no `in_reply_to`: it is outside the closed protocol field set; the nonce correlates request and reply), validates binding, boots, integer bounds, nonce state and the prior runner cutoff through `p.CheckLease` with `ReceivedMS: *request.SentMS`, drift 2000 ms and termination 5000 ms. This is a structural/runner-domain baseline, not a daemon measurement of reply delay: `sent_ms` and the prior cutoff belong to one runner boot, and a renewal at or past that cutoff is fenced `delayed_reply`. The runner enforces actual reply delay using its own receive time. The daemon records its separate issuance wall/boot-elapsed stamp, full validity deadline and `MarginNS` 7 s in `control_leases`, then commits before replying; expiry latches and reconcile barriers use that daemon clock, never runner timestamps. Same-nonce replay preserves the original reply and issuance without extending the deadline; refusals are fenced through `controlFence` and committed before the 409. Runner: `RequestLease` → POST → `ApplyLease`; renew every 5 s; cutoff `S + 13000`; the guardian enforces it independently. Every new expiry stop uses `execwire.ExpiryStopID(nonce)`: SHA-256 of `"lease-expiry:" + nonce`, first 16 bytes with UUIDv4 version/variant bits. Store late-renewal fencing, reconcile and runner termination therefore address the same latch. Daemon and runner timestamps are never compared across clock domains at issuance.

**Streams.** `runstream.Sinks` (`internal/runstream/sinks.go`, S1) keeps one `Sink` per attempt at `<state-dir>/streams/<attempt_id>.sink`, identity from the dispatch, limit 4 MiB. `Sink.Receive` appends through the fsync'd runner journal; S1 proves ack-after-durable with a kill -9 test before documenting it. Each persistent Store owns its sink set from `OpenWithOptions` through `Close`; reopening releases and reacquires journal locks rather than using a process-global registry. Owner reads use the Window-only `runstream.SinkReader`; `Store.Streams()` exposes a read-only view, while the writable sink remains package-private and serialized with finalization. The runner reserves the last 8 KiB of spool for one terminal `normalized{stream:"status", text:"spool_full"}` record, then requests stop and packs a failed manifest; promised native bytes are never dropped.

**Uploads, custody, finalize.** `BeginUpload` binds `result.identity`, manifest hash and inventory before bytes; blobs stage under `<artifacts-dir>/upload/<upload_id>/<sha256>`; `CommitUpload` builds `CustodyRequest{Sources: staged, Fingerprint}` and calls `CustodyResult`, which now always writes `artifact_results.current = 0` and sets `result_ack.MessageID = dispatchID(receipt_id, "ack")` so replay is byte-identical. Custody never terminalizes. `FinalizeAttempt` verifies: non-quarantined current-generation receipt; sink watermark ≥ claimed with equal digest; an `exit` observation; `boundary.quiescent`; no stop latch; live grant; current boots. Then CAS `result_pending→succeeded|failed` from `manifest.outcome`, event `dispatchID(receipt_id,"terminal")`, `dispatch_releases` (actor runner principal), `tasks.state = awaiting_review|reconciling`, and for `succeeded` an `artifact_result_heads` upsert. A crash between custody and finalize is classified `custody_committed_pending_finalization`; reconcile completes only when retained evidence proves the finalization requirements, never by rerunning the attempt. **Current-wire limitation:** for real-harness attempts the operative quiescence proof is the runner's own finalize. A runner that dies between custody commit and finalize leaves the attempt blocked (`action_required` after the replacement barrier) until it returns or the owner releases with verified provenance. A journal boundary field and channel-side attestation retention are follow-ups, not implemented here. The runner deletes the workspace only after `finalize` returns 200. **Custody limitation:** channel staging is directory-pinned, but `CustodyResult` still receives absolute source paths and performs its own `Lstat`; the subsequent copy is not covered by that staging pin. This is not a fully descriptor-relative custody path.

**Reconnect and replay.** Every runner→daemon call is keyed by `message_id` and answered from retained receipts; the runner journal is the outbox. On `Open()` the supervisor re-terminates any `launched` pgid lacking a terminal record (`TerminateProcessGroup`, guarded by `start_unix_ns`), sends `Hello.journals`, replays unacknowledged messages in order and journals `stale_generation|boot_mismatch` answers as `fenced` (recovery dir kept, no launch). Authenticated 4xx replay refusals retain an `outbox_refused` outcome without acknowledging or deleting the request; replay continues through later entries. A complete durable custody plan resumes begin/blob/commit/usage/finalize with stable IDs after restart, while legacy incomplete plans remain retained for reconciliation.

## 5. Owner workflow API and CLI

**Conventions.** Owner mTLS re-authenticated per request. Bodies carry `version:"workflow-provisional-v1"` and `message_id` (UUIDv4), which **is** the domain intent key: grant ID for approve, `DispatchRequest.ID`, `c.Request.ID`, `review.Decision.ID`, task ID, job ID. Store methods already replay by those keys, so a duplicate returns the same result even if the `owner_commands` receipt was lost; the receipt is written after the domain commit and served on replay with `Idempotent-Replay: true`; same `message_id` with another `request_sha256` → 409 `identity_conflict`. Preconditions: `expected_revision` (repository, eligibility), `expected_grant_id` (approve/restrict), `grant_id`+`grant_revision` (dispatch), `verification_id`+`selection_id` (review). Errors: 400 `malformed|invalid_query|invalid_id|invalid_bound`; 403 `identity_denied|boundary_refused`; 404 `not_found`; 409 `revision_conflict|identity_conflict|current_assignment|reconciliation_required|stopped|stop_latched|candidate_conflict|paused|eligibility_stale|superseded`; 422 authority Deny codes (e.g. `budget_exhausted`, `attempt_ceiling`, `no_eligible_tuple`, `runner_disabled`, `isolation_unsupported`, `development_isolation_refused`) with `detail` = Deny field; 503 `store_unavailable|busy`. Long work runs in `jobs` (single worker; a job `running` at startup becomes `failed:daemon_restart`), never inside the 2 s budget. Watch is short polling (`poll_after_ms`, CLI 500 ms); events keep durable sequence IDs so SSE can follow later.

**Guardian and termination.** `runner.Options.Boot string` (S2) makes `Create` use the supervisor boot instead of a fresh `id()`, so all journals of one process share the published boot; `Open` still records a restart boot and quarantines. ## 11. Integration order and prove-it-works scenarios

Merge order: PRs 108–112 and #113 → S0 → S1 → S2 → S3 → S4 → S6 → S5 → S7; S1–S4 and S6 develop concurrently from S0's branch, S5 from S1. `tests/system` (`//go:build system`; `scripts/m1-proof.sh` runs `go test -tags system -count=1 -timeout 90m ./tests/system/...`) builds the binaries with `CGO_ENABLED=0` into `/private/tmp/gaffer-m1-bin`, generates certificates with `gaffer identity keygen` and gives each scenario a fresh root under `/private/tmp/gaffer-system-<run>/`.

Commands S-04 reproduces:

```
gafferd --state-dir $R/state --artifacts-dir $R/artifacts --bootstrap-owner-cert $R/owner.crt
gafferd --state-dir $R/state --artifacts-dir $R/artifacts --listen 127.0.0.1:7443 --execution-listen 127.0.0.1:7444 \
  --tls-cert $R/daemon.crt --tls-key $R/daemon.key --endpoint https://localhost:7443 \
  --allow-development-profile=macos-sandbox-exec-dev --gateway-config $R/gateway.json --backup-dir $R/backups
gaffer identity invite --fingerprint <runner-fp> --json ; gaffer identity enroll --token <t> --cert $R/runner.crt --key $R/runner.key
gaffer repo register --profile $R/repo.json --expected-revision 0 --json
gaffer-runner serve --state-dir $R/runner --daemon https://localhost:7444 --daemon-fingerprint <fp> --cert $R/runner.crt \
  --key $R/runner.key --repository-root $R/roots --isolation-profile macos-sandbox-exec-dev --harness fake
gaffer-runner facts --state-dir $R/runner > $R/facts.json ; gaffer runner facts import --file $R/facts.json --expected-revision 0
gaffer flow run --repo greeting --base <sha> --brief-file $R/brief.txt --criterion greeting="greeting.txt says hello, gaffer" \
  --path greeting.txt --runner <runner-id> --harness fake --allow-development-isolation --json
```

- **S-02** enroll runner, register a disposable `file://` bare repo → job completes; revision 1
- **S-03** facts import; restart runner → `recovery_only` until re-import → `runner_sessions.mode`
- **S-04** happy path `flow run` (fake edit) → `assigned→starting→running→result_pending→succeeded`; stream records; blob bytes equal the file; head set; report verified; accept recorded; a second task dispatches
- **S-05** stop mid-run (`hang`) → cancel delivered ≤ 1 s; pgid gone; `stopping→cancelled`; released; retry admitted
- **S-06** SIGKILL gafferd during `running` → attempt `unknown`; hello + evidence → `expired` + release, or `result_pending` → custody → finalize; never two active attempts
- **S-07** SIGKILL gaffer-runner with live child → guardian kills on EOF; `Open()` re-terminates; `terminated` → `cancelled`; retry after facts re-import
- **S-08** proxy drops the first commit reply → same receipt, byte-identical ack, one custody row
